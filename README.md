# Simple Workflow MVP - 代码审查修复工作流

## 一、项目概述

本项目是一个基于多 Agent 协作的简单工作流最小可行版本（MVP），实现了「需求输入 → 生成代码 → 代码质量审查 → 代码修复优化」的端到端完整流程，用于演示和理解 Workflow 编排、Agent 间通信、状态管理等核心概念。

项目复用了 Code Agent 项目的代码生成与代码审查能力，通过标准化的 Agent 接口和共享状态上下文，实现了多智能体的串行协作。

## 二、流程说明

### 2.1 工作流程图

```
用户业务需求 → [编码Agent] → 初始代码 → [审查Agent] → 审查意见 → [修复Agent] → 最终优化代码
```

### 2.2 Agent 角色与职责

表格

| Agent 角色 | 核心职责 | 输入 | 输出 |
| --- | --- | --- | --- |
| 编码 Agent | 流程第一个节点，根据自然语言需求生成规范的 Python 代码 | 用户的业务需求描述 | 带注释的初始功能代码 |
| 审查 Agent | 流程第二个节点，从多维度对代码进行专业质量审查 | 编码 Agent 生成的初始代码 | 问题清单、优化建议与评分 |
| 修复 Agent | 流程第三个节点，根据审查意见针对性修复代码问题 | 初始代码 + 审查意见 | 修复优化后的最终代码 |

## 三、架构设计

### 3.1 核心模块

#### 1. 状态上下文（WorkflowState）

- 全局共享的数据容器，采用字典结构存储全链路的所有中间数据
- 所有 Agent 仅通过读写状态上下文实现消息传递，Agent 之间无直接依赖
- 支持动态新增字段，可灵活扩展不同业务场景的状态数据

#### 2. Agent 基类（BaseAgent）

- 定义统一的 `run(state)` 接口规范，约束所有 Agent 的输入输出格式
- 所有具体业务 Agent 均继承该基类，只需实现自身的业务逻辑
- 新增 Agent 节点无需修改工作流核心编排代码，架构扩展性强

#### 3. 工作流编排器（SimpleWorkflow）

- 接收 Agent 节点列表，按顺序依次执行每个节点
- 负责状态上下文的生命周期管理与节点间传递
- MVP 版本实现基础的顺序流程控制，后续可扩展条件分支、循环、并行等高级调度能力

### 3.2 设计特点

- **低耦合**：Agent 之间无直接调用，仅通过状态上下文交互，职责边界清晰
- **可扩展**：新增业务 Agent 只需继承 BaseAgent 并加入执行列表，无需改动核心代码
- **易调试**：全链路状态可追溯，每个节点的输入输出都完整保存在上下文中
- **可复用**：Agent 能力可复用到其他工作流场景，支持快速搭建新流程

## 四、使用说明

### 4.1 环境依赖

- Python 3.8 及以上版本
- 第三方依赖：`dashscope`（通义千问官方 SDK）

安装依赖命令：

```
pip install dashscope
```

### 4.2 配置步骤

1. 打开项目根目录下的 `config.py` 文件
2. 将 `DASHSCOPE_API_KEY` 字段的值替换为自己的通义千问 API 密钥
3. 可根据需求调整 `MODEL_NAME` 字段切换使用的大模型

### 4.3 运行方式

在项目根目录的终端中执行入口文件：

```
python main.py
```

运行后将依次执行三个 Agent 节点，最终在终端输出完整的结果汇总。

### 4.4 自定义需求

修改 `main.py` 文件中 `init_data` 里的 `requirement` 字段，即可输入任意代码需求，运行完整的代码审查修复工作流。

示例：

```
init_data = {
    "requirement": "写一个函数，实现快速排序算法"
}
```

## 五、MVP 版本说明

本版本为最小可行产品，已完整实现所有必须要求：

- 3 个 Agent 协作完成端到端完整业务流程
- 通过全局状态上下文实现 Agent 间的消息传递与状态共享
- 支持基本的顺序流程控制，工作流编排清晰
- 基于基类的架构设计，支持新增 Agent 与修改流程顺序
- 复用了已有 Code Agent 项目的代码生成、代码审查能力
